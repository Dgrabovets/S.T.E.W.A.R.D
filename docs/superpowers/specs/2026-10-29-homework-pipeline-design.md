# Процесс домашних заданий от А до Я: единый конвейер

Дата: 2026-10-29. Статус: черновик на проверке у владельца.

## Цель

Домашнее задание проходит один понятный путь, и почти весь он выполняется сам. Владелец делает три вещи: смотрит и правит готовую работу, сдаёт её в LMS, отмечает «Сдано». Всё остальное делает Steward. На любом шаге видно, что происходит и что дальше. Сданная работа становится образцом для следующих заданий того же предмета.

## Что решил владелец, а что допущено

Решено владельцем:
- Работа готовится сама, сразу после того как найдено несданное задание (не по кнопке).
- Подход «единый конвейер на задание» вместо набора отдельных отметок.
- Образцы привязаны к предмету.
- Состояния «просмотрена» у расшифровок нет, ни автоматического, ни ручного.

Допущено мной, нужна проверка (в списке вопросов в конце):
- Расшифровки сортируются по состоянию заданий: занятия, где всё сдано, уходят вниз списка и приглушаются. Это замена «откатываются вниз» без отметки «просмотрено».
- Сдачу в LMS Steward не выполняет, только подсказывает.

## Конвейер задания

Состояние задания не хранится отдельным полем, а выводится из того, что лежит на диске. Хранятся только две отметки владельца, как сейчас.

| Шаг | Как определяется | Кто делает |
|---|---|---|
| Найдено | задание есть в `items/<занятие>.json` | Steward: расшифровка, разбор, поиск заданий, условие из LMS |
| Готовится | работа сейчас пишется агентом | Steward |
| Готово | в папке занятия есть файл `Задание N.*` | Steward |
| Проверено | есть отчёт `.check/report.md` | Steward, автоматически после «Готово» |
| Сдано | LMS показывает «сдано» или стоит отметка `submitted` | LMS сам или владелец одной кнопкой |

Отдельно: «В архиве» (отметка `archived`) убирает задание из конвейера и из напоминаний.

## Автоматика

В фоновую задачу `Steward.Lms` после шага `extract` добавляется шаг `prepare`:
1. Берёт найденные задания, которые не сданы, не в архиве и у которых нет файла работы.
2. Формат берётся из формата предмета по умолчанию. Предмет с форматом «Не готовить» пропускается.
3. Подготавливает работу с методичками и образцами предмета и условием из LMS.
4. Сразу запускает проверку и сохраняет отчёт.
5. Показывает уведомление в трее: «Готова работа: предмет, задание».

Лимит расхода: новая настройка `MaxPreparePerRun` (по умолчанию 2 работы за запуск). Остальные ждут следующего запуска.

Если не хватает входных данных (нет расшифровки, не выгружено условие), задание остаётся «Найдено» с подсказкой, чего именно не хватает. Ошибка агента показывается на карточке и в журнале, повтор на следующем запуске, не чаще трёх раз подряд.

Кнопка «Подготовить задание» остаётся для случаев, когда нужен другой формат или дополнительное указание, и для «Переделать».

## Расшифровки

Состояния «просмотрена» нет. Список занятий на вкладке «Расшифровки» упорядочен по пользе: сверху занятия с несданными заданиями, ниже занятия без заданий, внизу занятия, где всё сдано (приглушены). Внутри групп порядок по дате, свежие выше. Читалка не меняется.

## Сдано и образец

1. Когда задание получает состояние «Сдано», его файл работы по умолчанию становится образцом предмета. Ничего делать не нужно.
2. Если владелец сдал свою доработанную версию, в меню карточки есть «Указать файл сданной работы». Выбранный файл заменяет образец этого задания.
3. Файл копируется в `data/homework/samples/<предмет>/` и регистрируется в хранилище материалов как «Образец» с идентификатором `sample:<занятие>:<номер>` и пометкой «сдано». Дубли по тому же заданию заменяются.
4. При подготовке следующей работы берутся: все включённые образцы, добавленные вручную, и два последних сданных образца того же предмета. Образцы других предметов не берутся.
5. В окне «Методические указания» сданные образцы видны, их можно отключить или удалить, как любые другие.

## Карточка занятия

- Строка шагов конвейера: Найдено, Готово, Проверено, Сдано. Текущий шаг выделен, у задания с ошибкой или нехваткой данных подсказка одной строкой.
- Одна главная кнопка по состоянию: «Посмотреть работу», затем «Отметить сданным».
- Остальное в меню «…»: открыть в LMS, скопировать условие, проверить заново, результат проверки, переделать, указать файл сданной работы, в Singularity, в архив, удалить готовое.
- Напоминания о сроках на «Статусе» остаются как есть.

## Данные и миграция

- Новые данные: `data/homework/samples/<предмет>/` и записи в `guides.json` с видом «Образец». Старых данных менять не нужно.
- `item-states.json`, `created.json`, `lesson-states.json` не меняются. Числовые значения перечислений не переупорядочиваются.
- Уже готовые работы по сданным заданиям один раз превращаются в образцы при первом запуске после обновления.

## Безопасность

- Агент по-прежнему получает только Read и Write, образцы и условия для него только для чтения, расшифровки и тексты работ идут как данные, а не инструкции.
- Запись в Singularity по-прежнему под флагом `CreateTasks`.
- Секреты не читаются и не показываются.

## Проверка

Тесты: вывод шага конвейера по содержимому папки; сортировка занятий; регистрация и замена образца; выбор образцов для подготовки (по предмету, лимит два последних плюс ручные); лимит `MaxPreparePerRun`; пропуск сданных, архивных и уже готовых заданий. Снимки DevTools карточки в каждом шаге.

## Вне рамок

Сдача работы в LMS за владельца; автоматическое включение `CreateTasks`; мессенджеры и «Ближайшие пары».

## Вопросы владельцу

1. Устраивает ли замена «откатываются вниз» сортировкой по заданиям (всё сдано, значит вниз)?
2. Устраивает ли лимит 2 работы за запуск и уведомление в трее по каждой готовой работе?
