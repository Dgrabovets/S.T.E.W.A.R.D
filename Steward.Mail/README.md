# Steward.Mail

Утром и вечером проверяет учебную почту `dgrabovets-26@ranepa.ru` и:

- на живое письмо от человека ставит задачу в SingularityApp «Пришёл ответ от …, нужно ответить: «тема»» (высокий приоритет);
- на отзыв или оценку в LMS (папка «Преподаватели») ставит задачу «Отзыв преподавателя (…): «задание» — посмотреть»;
- показывает уведомление Windows со сводкой. Если ничего важного нет, молчит.

Письма только читаются: статус «прочитано» не меняется. Обработанные письма запоминаются в `processed.json`, поэтому задачи не дублируются.

Запускает программу приложение в трее ([`Steward`](../Steward/README.md)): при его старте и каждый день в 09:00 и 19:00. После проверки утилита записывает итог в общий файл статуса `data/status/mail.json` ([формат](../Steward.Status/README.md)), по нему приложение показывает строку «Почта» и сообщает об ошибке. Пробный прогон `--dry-run` статус не меняет.

## Настройка

1. **Пароль приложения для почты.** Яндекс ID учебного аккаунта → «Безопасность» → «Пароли приложений» → «Почта». В настройках ящика «Почтовые программы» должен быть включён доступ по IMAP.
2. **Токен SingularityApp.** Личный кабинет → «API Access» (нужен тариф Pro/Elite).
3. Скопируй `appsettings.example.json` в `appsettings.json` и вставь пароль и токен. Если задачи должны падать в конкретный проект, укажи `ProjectId` (список: `GET /v2/project`). Иначе оставь `null`, и задачи попадут во «Входящие».

## Сборка и запуск

Нужен .NET 10. Команды запускаются из папки `Steward.Mail`. Программа собирается в `publish/` внутри репозитория, на диск C: ничего не пишется.

```powershell
dotnet publish -c Release -o publish

# Пробный прогон: только лог, без задач и без запоминания писем
publish\Steward.Mail.exe --dry-run
type publish\mail-check.log
```

Чтобы приложение запускало проверку само, поменяй `"enabled": false` на `true` у задачи `mail` в [`config/jobs.json`](../config/jobs.json) и перезапусти приложение. Запустить проверку один раз можно кнопкой «Запустить» в разделе «Статус».

`install-schedule.ps1` устарел: он ставил то же расписание в Планировщик Windows, и вместе с приложением проверка шла бы дважды. Скрипт отказывается работать без ключа `-Force`.

## Тесты

```bash
dotnet test tests/Steward.Mail.Tests
```

Тесты не ходят ни в почту, ни в Singularity: проверка идёт на подделках (`MailChecker` целиком, классификатор, сборка задач и сводки, список обработанных писем, запрос к API на заглушке HTTP). Чтение по IMAP (`ImapMailReader`) и уведомление Windows (`ToastNotifier`) тестами не покрыты: им нужны настоящий сервер и рабочий стол.

## Как разбираются письма

| Где лежит / от кого | Что происходит |
|---|---|
| Папка «Преподаватели» | Задача «посмотреть отзыв» |
| «Входящие», отправитель — человек | Задача «нужно ответить» |
| «Входящие», noreply/системные адреса (`IgnoredSenders`) | Только строка в сводке |
| «LMS-уведомления» | Игнорируется: это шум, его уже разложило правило почты |
