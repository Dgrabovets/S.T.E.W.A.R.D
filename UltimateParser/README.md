# UltimateParser

Переносит расписание из Google Sheets в Singularity. Сейчас читается колонка `РКИ-2-26`: каждая пара становится задачей с датой, временем и длительностью. Время в таблице — московское. Ссылка, прикреплённая к ячейке, попадает в описание словом «Ссылка», которое открывается по нажатию. У каждой пары стоит напоминание за 15 минут. Повторный запуск обновляет уже созданные задачи. Если ячейка опустела, задача отмечается выполненной и остаётся такой: по ней на каждой сверке снова пишется пометка. Когда этот предмет ещё есть сегодня, в его задаче пишется, что это перенос. Иначе пометка «отмена или перенос» попадает в следующую пару, в том числе в пару, которую этот же прогон удалит и создаст заново. Перед закрытием прошедшего занятия в него записываются правки из таблицы и эта пометка. Выполненная задача прошедшего занятия после этого не меняется. Если ячейка всё ещё содержит занятие, время ещё не прошло, а задача уже выполнена, она удаляется и создаётся заново из таблицы. Прошедшая пара текущей недели создаётся и сразу отмечается выполненной. Пара более ранней недели не создаётся.

Таблица должна быть доступна по ссылке. Сервис скачивает CSV без аккаунта Google. Если доступ закроют, синхронизация остановится, пока ссылку снова не откроют.

## Токен Singularity

В личном кабинете Singularity создайте токен с доступом к сущностям «Проект» и «Задача» на чтение и запись. Скопируйте `.env.example` в `.env` и вставьте токен в `SINGULARITY_TOKEN`. Файл `.env` не коммитится.

Задачи попадают в проект с названием из `PROJECT_TITLE` (по умолчанию `Расписание`). Если такого проекта нет, сервис его создаёт. Занятие из объединённой ячейки попадает в каждую группу этого диапазона.

Проект находится по ключу `up-project:<колонка>` в его `externalId`, а не только по названию. Если найден проект с нужным названием и без ключа, сервис один раз записывает ему ключ. Дальше проект можно переименовать и переносить между проектами, и сервис не создаст дубль. Новый проект создаётся на верхнем уровне. Чтобы создавать его внутри другого проекта, укажите в `PROJECT_PARENT_ID` идентификатор родителя (`P-...`). Уже существующий проект настройка не двигает.

## Теги предметов

По умолчанию выключены. Если задать `SUBJECT_TAGS=true`, на каждую пару ставится тег с названием предмета без типа занятия: из `Гейм-дизайн (Практика)` получается тег `Гейм-дизайн`. Нужного тега нет — он создаётся. Теги, которые вы поставили на задачу сами, сохраняются. Задачи, созданные раньше, получают тег при ближайшей сверке. Токену нужен доступ к сущности «Тег» на чтение и запись. Если доступа нет, сверка пишет предупреждение в журнал и идёт дальше без тегов.

## Запуск

Постоянно, сразу один прогон и дальше каждые `SYNC_INTERVAL_MINUTES` минут (сейчас 5):

```bash
docker compose up -d
```

Один прогон:

```bash
docker compose run --rm sync --once
```

Логи: `docker compose logs -f sync`.

После правок кода сервиса пересоберите образ: скрипт входа запускает контейнер с `--no-build`, поэтому без пересборки он продолжит работать на старом коде.

```bash
docker compose build
```

Иконка в трее показывает статус всех задач репозитория: расписания и задач из [`config/jobs.json`](../config/jobs.json), которые приложение запускает само (например, проверка почты [`MailToSingularity`](../MailToSingularity/README.md)). Щелчок по иконке открывает быстрый статус, двойной щелчок или пункт «Открыть приложение» главное окно с разделами «Статус», «Идеи», «ДЗ» и «Журнал». Сбой любой включённой задачи делает иконку красной и даёт уведомление. Как запускаются задачи и в каком формате они пишут статус, описано в [`Status`](../Status/README.md).

При входе в Windows задача планировщика `UltimateParser Sync` запускает `start-sync.ps1`: скрипт дожидается Docker, поднимает контейнер и открывает иконку в трее. Иконка пересобирается только если её исходники новее собранного файла, поэтому вход не ждёт `dotnet publish`. Зелёная иконка значит, что синхронизация работает. Подсказка показывает время последнего прогона. Пункт «Логи» открывает журнал. Если прогон падает, появляется уведомление: по нему открывается текст ошибки. Когда в таблице занятие убрали или перенесли, а также когда изменилась уже созданная пара, иконка один раз показывает уведомление «Расписание изменилось». Добавление новых пар уведомления не вызывает. Момент последнего показанного уведомления хранится в `data/last-notified.txt` в корне репозитория, поэтому после перезапуска иконки старое не повторяется. При первом запуске история журнала не показывается. У контейнера стоит `restart: unless-stopped`, поэтому дальше его поднимает сам Docker.

Тесты разбора сетки и сверки:

```bash
dotnet test
```
