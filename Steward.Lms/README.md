# Steward.Lms

Выгружает занятия из LMS РАНХиГС и расшифровки записей из MTS Link для домашних заданий. Результат кладётся в `data/homework`, дальше работают окно «Форматы заданий» и `Steward.Homework.Tasks`.

## Как работает

1. Входит в LMS обычным запросом по логину и паролю из `lmssettings.json`. Браузер не нужен.
2. Читает список курсов и на странице «Ссылка на занятия МТС Линк» каждого курса собирает прошедшие вебинары. Они записываются в `data/homework/lessons.json`: предмет, дата, подпись, длительность, ссылка на запись.
3. Новому занятию ставится отметка в `lesson-states.json`: записи короче `MinLessonMinutes` (10 минут по умолчанию) получают «Не забирать», остальные «Ждёт решения».
4. Для занятий с отметкой «Забирать» и без расшифровки открывает запись в Chromium без окна под сохранённым входом в MTS Link и записывает расшифровку в `data/homework/transcripts/<id>.txt`: резюме встречи и реплики со временем.

Отметка ставится на плитке предмета в выпадающем списке: «Ждёт решения», «Расшифровывать» (расшифровка, разбор и домашние задания), «Только анализ» (расшифровка и разбор без заданий), «Задания из LMS» (расшифровки нет, задания берутся из LMS и готовятся), «Не нужно», «Завершён». Расшифровки подтягиваются у предметов с отметкой «Расшифровывать», от свежих занятий к старым, по `MaxFetchPerRun` (6) за запуск.

## Задания, тесты и задачи в SingularityApp

Состояние работ в LMS программа только читает. На страницах `Задания` и `Тесты` каждого курса она берёт название, срок, состояние («Отправлено для оценивания», «Нет ответа на задание», «Черновик») и оценку, а снимок кладёт в `data/homework/activities.json`.

В SingularityApp она только записывает:
- на несданную работу предмета с отметкой «Расшифровывать» или «Задания из LMS» заводится задача `ДЗ: …` или `Тест: …` со сроком, темой, состоянием и ссылкой на страницу работы в LMS. Внешний ключ задачи `lms:assign:<номер>` или `lms:quiz:<номер>` не даёт завести дубль, в том числе если задачу удалили или перенесли в архив;
- когда работа сдана, открытая задача на неё закрывается.

Пока в `lmssettings.json` стоит `"CreateTasks": false`, программа ничего не пишет в SingularityApp, а в журнале показывает, что завела бы и что закрыла бы. Посмотреть можно командой `Steward.Lms.exe tasks --dry-run`. Чтобы включить запись, нужны `Singularity:Token` (тот же, что у почты) и `"CreateTasks": true`. Заметки, которые уже есть в SingularityApp, программа не заменяет, а дописывает в конец: написанное вручную остаётся.

Шаг `publish` (в конце обычного запуска) заводит задачу `ДЗ: …` по каждому найденному несданному заданию (внешний ключ `hw:<занятие>:<номер>`, повторный запуск дублей не делает). Задания, которые ждут подтверждения, сданные и убранные в архив задач не получают. Когда по заданию есть готовый файл работы, в заметку уже заведённой задачи один раз дописывается ссылка на него. Сбой на одном задании или заметке попадает в журнал и не останавливает остальные. При `"CreateTasks": false` в SingularityApp ничего не пишется, в журнале только строки «Завёл бы: …» и «Добавил бы ссылку на готовую работу…».

## Конвейер домашних заданий

Задание идёт «Найдено → Готово → Проверено → Сдано»; сомнительное задание останавливается на «Найдено» с пометкой «Нужно подтвердить» (подробности и поля `evidence`, `confidence`, `doubt` в [Steward.Homework](../Steward.Homework/README.md)). Обычный запуск делает по порядку: `sync`, `analyze`, `extract`, `prepare`, `publish`. Шаг `prepare` берёт не больше `MaxPreparePerRun` работ (по умолчанию 2), укладывается в `PrepareBudgetMinutes` (по умолчанию 20 минут) и готовит только занятия не старше `PrepareMaxAgeDays` дней (по умолчанию 21, граница включается, 0 значит без ограничения; старое занятие можно подготовить кнопкой в приложении). Все три настройки лежат в `lmssettings.json`, старый файл без них читается со значениями по умолчанию. Разбор и поиск заданий запускают агента с правом записи в `items` и `analysis`, подготовка и проверка — только в папки работ занятий (подробности в [Steward.Homework](../Steward.Homework/README.md)). Ошибка или истёкший срок (5 минут) шага `publish` не роняет запуск: итог статуса с уведомлениями о готовых работах всё равно записывается.

- Пока `prepare` работает, держится `data/homework/prepare.lock`; второй запуск и кнопки в приложении (подготовка, прикрепление, «Проверить заново») ждать не будут и сообщат, что идёт подготовка в фоне.
- Неудачи агента считаются в `prepare-attempts.json`: после трёх подряд задание ждёт владельца, успех сбрасывает счётчик. Работа, которая не уложилась в срок, попытку не теряет.
- Сданные работы становятся образцами предмета (`samples/<предмет>/`, отметка в `sample-registered.json`), замечания лежат в `remarks/<предмет>.json` и `remarks/_all.json`, подтверждения в `item-confirmed.json`, правки условий в `item-overrides.json`.
- Таймаут задачи `lms` в `config/jobs.json` равен 90 минутам: разбор и поиск заданий могут занять до часа, подготовка ограничена 20 минутами.
- Задачи в Singularity по найденным заданиям заводятся только при `"CreateTasks": true`. Этот флаг включает только владелец: Steward его не включает и не предлагает. При `false` в журнале только строки «Завёл бы…».

## Настройка

1. Скопируй `lmssettings.example.json` в `lmssettings.json` и впиши логин и пароль LMS. Файл в `.gitignore`.
2. Поставь браузер для Playwright (один раз, около 530 МБ): `Steward.Lms.exe install`. По умолчанию он лежит в `..\Playwright` рядом с репозиторием, место меняется параметром `BrowsersPath`.
3. Войди в MTS Link (один раз): `Steward.Lms.exe login`. Откроется окно, нажми «Войти через SSO» и войди по корпоративной почте. Вход сохраняется в `data/lms/mts-state.json`. Это ключ к аккаунту, файл в репозиторий не попадает.
4. Собери программу: `dotnet publish Steward.Lms -c Release -o Steward.Lms/publish`. Задача `lms` в `config/jobs.json` запускает её при старте приложения и дважды в день.

Когда MTS Link перестанет помнить вход, программа остановится с понятным сообщением в журнале: повтори пункт 3.

## Описания заданий

При запуске `tasks` (и обычном запуске) программа читает страницы несданных заданий, достаёт текст условия и прикреплённые файлы и кладёт их в `data/homework/assignments/<номер работы>`: `assignment.md` и скачанные файлы (для Word и презентаций рядом лежит текстовая копия). Эти файлы читает Claude при поиске заданий и при подготовке работ.

## Команды

| Команда | Что делает |
|---|---|
| без аргументов, `sync` | собирает занятия, забирает расшифровки, разбирает занятия и записывает заметки |
| `install` | ставит Chromium для Playwright |
| `login` | открывает окно входа в MTS Link и сохраняет вход |
| `extract` | добавляет задания из LMS: работы с написанным условием или приложенным файлом копируются в `data/homework/items` без агента (из расшифровок задания сами не берутся); то же делает обычный запуск |
| `task <занятие> <номер>` | заводит задачу в SingularityApp по найденному заданию, по кнопке «В Singularity» |
| `note-task <занятие> <номер>` | заводит задачу в SingularityApp по заданию из отрывка расшифровки (номер в разборе занятия), не добавляя его в список заданий: кнопка «Только в Singularity» на вкладке «Задания» читалки |
| `page <адрес> <файл>` | сохраняет страницу LMS в файл (для разработки) |
| `analyze` | просит Claude разобрать занятия с расшифровкой и без разбора (`MaxAnalyzePerRun`, 3 за запуск) и пишет разбор в `data/homework/analysis` |
| `prepare` | готовит работы по найденным несданным заданиям (`MaxPreparePerRun`, 2 за запуск) и сразу их проверяет; весь шаг ограничен `PrepareBudgetMinutes` (20 минут, вместе с разбором и поиском заданий укладывается в таймаут задачи `lms`, 90 минут), берутся только занятия не старше `PrepareMaxAgeDays` (21 день), по истечении работа агента останавливается, готовое сохраняется, запуск идёт дальше. По каждой работе пишет строку «Готова работа: предмет, задание»; то же делает обычный запуск после `extract` |
| `publish` | записывает разборы в заметки SingularityApp и ссылки на готовые файлы в задачи ДЗ (при `CreateTasks`, иначе только пишет в лог) |
| `tasks [--dry-run]` | читает работы из LMS и заводит и закрывает задачи в SingularityApp, с `--dry-run` только показывает |
| `probe <адрес записи>` | показывает запросы страницы записи к расшифровке (для разработки) |
| `get <адрес записи> <адреса gw.mts-link.ru…>` | читает ответы MTS Link на запросы (для разработки) |

## Прогресс запуска

В обычном запуске процесс пишет, на каком он шаге, в `data/status/progress/lms.json` (шаги: Занятия, Расшифровки, Разбор, Задания, Работы, Заметки; счётчик и название обрабатываемого занятия). Страница «Статус» показывает их, пока процесс работает. Ошибка записи прогресса запуск не ломает. В журнале по каждому предмету пишется строка «LMS: предмет: заданий N, сдано M; тестов K, пройдено L»: по ней видно, что именно разобрал LMS-парсер. Работа с оценкой считается сданной.
