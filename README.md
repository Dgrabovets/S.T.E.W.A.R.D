# UltimateParser

Переносит расписание из Google Sheets в Singularity. Сейчас читается колонка `РКИ-2-26`: каждая пара становится задачей с датой, временем и длительностью. Время в таблице — московское. Ссылка, прикреплённая к ячейке, попадает в описание словом «Ссылка», которое открывается по нажатию. У каждой пары стоит напоминание за 15 минут. Повторный запуск обновляет уже созданные задачи. Если ячейка опустела, задача отмечается выполненной и остаётся такой: по ней на каждой сверке снова пишется пометка. Когда этот предмет ещё есть сегодня, в его задаче пишется, что это перенос. Иначе пометка «отмена или перенос» попадает в следующую пару, в том числе в пару, которую этот же прогон удалит и создаст заново. Перед закрытием прошедшего занятия в него записываются правки из таблицы и эта пометка. Выполненная задача прошедшего занятия после этого не меняется. Если ячейка всё ещё содержит занятие, время ещё не прошло, а задача уже выполнена, она удаляется и создаётся заново из таблицы. Прошедшая пара текущей недели создаётся и сразу отмечается выполненной. Пара более ранней недели не создаётся.

Таблица должна быть доступна по ссылке. Сервис скачивает CSV без аккаунта Google. Если доступ закроют, синхронизация остановится, пока ссылку снова не откроют.

## Токен Singularity

В личном кабинете Singularity создайте токен с доступом к сущностям «Проект» и «Задача» на чтение и запись. Скопируйте `.env.example` в `.env` и вставьте токен в `SINGULARITY_TOKEN`. Файл `.env` не коммитится.

Задачи попадают в проект с названием из `PROJECT_TITLE` (по умолчанию `Расписание`). Если такого проекта нет, сервис его создаёт. Занятие из объединённой ячейки попадает в каждую группу этого диапазона.

## Запуск

Постоянно, сразу один прогон и дальше каждые `SYNC_INTERVAL_MINUTES` минут (сейчас 5):

```bash
docker compose up -d
```

Один прогон:

```bash
docker compose run --rm sync --once
```

Логи: `docker compose logs -f sync`.

При входе в Windows задача планировщика `UltimateParser Sync` запускает `start-sync.ps1`: скрипт дожидается Docker, поднимает контейнер и открывает иконку в трее. Зелёная иконка значит, что синхронизация работает. Подсказка показывает время последнего прогона. Пункт «Логи» открывает журнал. Если прогон падает, появляется уведомление: по нему открывается текст ошибки. У контейнера стоит `restart: unless-stopped`, поэтому дальше его поднимает сам Docker.

Тесты разбора сетки и сверки:

```bash
dotnet test
```
